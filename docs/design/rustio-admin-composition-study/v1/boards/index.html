rustio-admin × Composition 3.1

Can rustio-admin adopt RustIO's final visual language and keep its own, richer components? Yes. The tokens already match; what differs is scale and composition, and both are reachable without touching a single route.

A

The short answer

Yes. rustio-admin's current HEAD already shares RustIO's palette value for value — the same #F1F1EE ground, the same #1F5797 blue, the same lines, the same near-white rail. What separates the two products is not colour but scale and composition: rustio-admin runs a 16px/44px "operator comfort" scale with 36px titles, boxed page headers, 56–64px rows, pill badges and hover-revealed icon actions; RustIO 3.1 runs 15px/38px, unboxed heads with the action beside the title, 48px rows, dot badges and quiet text actions.

One real blocker, and it is a document, not code. rustio-admin's docs/design/VISUAL-CONTRACT.md (v2.1) mandates 44px controls and forbids any text under 14px and any 36/38px control height. RustIO 3.1 is 38px controls and 13px mono labels. The two contracts contradict each other on exactly the values that make the family read as one. The contract is already stale on its own terms (it still describes a burnt-copper accent, a teal predecessor and a dark theme that HEAD has removed), so amending it is overdue regardless. Nothing else blocks adoption.

E

Primary colour — one proposal

Keep #1F5797. rustio-admin already uses RustIO's exact blue, and the family reads as one only if the two products share it. A different blue for rustio-admin alone would undo the convergence this study is for.

The one candidate worth recording is the slightly cleaner azure explored for RustIO (#0F5FA8, hover #0B4A84, soft #DCEBFB, line #A9CBEF, focus #2D7FDC). Measured: white on fill 6.5:1 (current 7.3:1), on the page ground 5.8:1 (current 6.5:1), focus ring on blue-soft 3.3:1 (current 3.5:1) — all pass, all slightly lower. It is marginally livelier and marginally less serious; on an eight-hour admin that is not a trade worth making, and status separation is unchanged either way because the greens, ambers and reds do not move. If it is ever adopted, adopt it in RustIO first and let rustio-admin inherit it through the alias layer.

F

Converge vs. remain

Visually converge

  • Page head (unboxed, action beside title)
  • Find row and data-surface head on list pages
  • Table geometry, mono heads, quiet text row actions
  • Badges and pills → dot badges
  • Buttons and inputs → 38 / 31px
  • Cards flat, radius 14, 16px padding
  • Fieldset bands with mono headings
  • Empty states inside the surface
  • Ink ramp, danger red, shadows
  • Rail item height, rail head level with the masthead

Remain product-specific

  • Two-row header with the module row
  • ⌘K search palette and its trigger
  • Account dropdown menu
  • Filter dropdown panels (FK autocomplete, multi-select, date range), More filters, Reset
  • Sort dropdown, direction toggle, rows per page
  • Bulk selection and the bulk bar
  • Three save variants; History · Delete · Cancel text actions
  • Inline related sections
  • Permission matrix, session list, API cards, history diffs, health, DB browser, feature flags, notifications, docs viewer, view designer
  • Full-width footer with system links and identity
  • AdminTheme override surface and rio-theme emission
