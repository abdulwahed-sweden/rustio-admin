Page composition — redesigned on the frozen theme

The visual system is accepted. What the pages still carry is the old composition: boxed heads, toolbars that duplicate the table, hidden workflow, forms that grey out their most important facts. This study critiques each page as it renders today and recomposes it with the same tokens, the same capabilities and the same shell.

B

Strongest structural problems found

#ProblemWhere
1The page's real work is hidden. On Jobs the seven workflow actions (Diagnosed → Collected) only exist inside a bulk bar that appears after a checkbox is ticked; the visible controls are Sort and rows-per-page. When a selection exists, two strips stack (bulk bar + sort strip).Jobs
2A whole strip for controls the table already has. The grey data-surface head carries Sort / Direction / 50 per page. Column headers already sort; rows-per-page belongs with pagination. The strip costs 56px on every list and says nothing.Jobs, every list
3Three filters, one hidden. The find row shows the first two filters and folds the third into "More filters" — a rule written for ten filters applied to three.Jobs
4Facts shown as broken inputs. The form renders read-only fields (status, quote approved, overdue — the shop's three most important facts) as disabled, greyed controls at the bottom of the card.Form
5The action bar in the middle of the page. Save sits between the fields and the related sections (Quotes, History), so the page's end is not where its action is; inline rows still use icon-only Edit/Delete.Form
6Meaning-blind booleans. overdue = yes renders as a green pill; status renders as in_progress. The list cannot tell a good true from a bad one and shows the wire value for choices.Jobs
7A registry dressed as a dashboard. Four stat tiles (Models, Total rows, Recent events, version) above a table whose rows repeat the app label and count fields; Docs is the page's blue button.Dashboard
8The shop's permissions behind a disclosure. The five workflow permissions (diagnose, quote, approve, repair, collect) are collapsed under "Other permissions (5)"; the matrix is a bordered table inside a bordered card.Groups
9Five facts, one card each. Sessions are stacked cards with a four-column definition list and a footer per session; the current one is a large blue block.Sessions
10Identical endpoint blocks per model. Every API card repeats the same five endpoint rows with a glyph tile; the fields table is the only thing that differs.API surface
11Narrow pages spend the screen on chrome. At 390 the list page stacks two full-width head buttons, three lines of filters and a two-line sort strip before the first row.Narrow
12Leads that say nothing. "All jobs in FixShop.", "Operator accounts — role, last sign-in, and MFA enrolment" (columns the table does not have), and a users grid whose head rule is broken into segments.Lists
